# Milestone 13 — Achievements, gallery and certificates

Latest verification: see [Milestone 16 security/testing](security-performance-testing.md) and [the roadmap](development-roadmap.md). Earlier failure counts and continuation scopes below describe their original checkpoint.

Public `/achievements` and `/gallery` show published, unarchived `clubShowcase` entries. Teachers manage their own content and admins manage all at `/dashboard/teacher/showcase`. Entries include kind, title, description, past/current UTC calendar date (2000 onward), optional HTTPS image for achievements and required HTTPS image for gallery, published flag and optimistic version. Names/descriptions are original content; UI is bilingual. Images follow the existing externally hosted HTTPS policy, use no-referrer, and are not fetched by Express. Publish only college-approved material. Archive is soft and confirmed; ownership/timestamps cannot be supplied in bodies.

Certificates are issued at `/dashboard/teacher/certificates` after selecting an owned published event and a registered participant marked present. Admins can manage all events. The server rechecks that the event has started, the registration belongs to it and attendance is present. It derives name, event title/date, recipient, owner and issue timestamp from server records; request bodies contain only event and registration IDs. Issue is idempotent: the natural registration ID is the unique `certificates._id`. A cryptographically random 256-bit verification ID is separately reserved as `certificateVerification._id`, guaranteeing database uniqueness without an index migration.

Issuance uses the existing MongoDB transaction infrastructure (Atlas/replica-set required). It touches the same event and registration documents used by attendance workflows, with private `certificateTick` counters, so concurrent cancellation/attendance correction conflicts with issuance. The verification pointer and certificate insert commit together or roll back together. Concurrent/repeated requests return the same certificate. A revoked certificate is never reissued under a new ID.

`/dashboard/student/certificates` lists only the session account's certificates; teacher/admin own-history access is also allowed. Earned certificate history does not require current membership approval. Staff list only certificates for their owned events; admins see all. Full names are limited to these authorized views. Certificate validity is checked against current registered/present attendance and a currently published/unarchived source event, as well as permanent explicit revocation. Correcting attendance to absent immediately makes online verification invalid. Staff may permanently revoke even a certificate already invalidated by an attendance correction. Version checks prevent stale revocation.

The native-dialog certificate preview is rendered as a direct body portal for isolated printing. **Print or save PDF** opens the browser's print dialog, including its Save as PDF option. Named A4 landscape print styles apply only while the certificate preview is open; navigation, dialogs/buttons and unrelated private content are excluded. This is a printable browser-generated PDF, not a digitally signed PDF or a background PDF service. Printed documents can become stale, so they include the authoritative verification URL and instruction to check current validity.

Public `/certificates/verify` and `/certificates/verify/[token]` verify the opaque ID. Public JSON exposes only ID, event title/date, issue timestamp, recipient initials and current validity. It excludes full name, account/student IDs, registration/owner IDs, email, phone and review/attendance metadata. Verification confirms the ledger entry, event, initials and current validity; it is not proof of full personal identity. College staff can compare full recipient details privately when necessary. All output renders as plain text, and IDs are strictly validated.

API:

- `GET /api/showcase?page=1&kind=achievement|gallery` — public, explicit projections.
- `GET/POST /api/manage/showcase`, `PUT/DELETE /:id` — staff ownership/admin, versions and trusted mutation Origin.
- `GET /api/own/certificates?page=1` — session owner only.
- `GET/POST /api/manage/certificates`, `PATCH /:token/revoke` — scoped staff/admin, trusted mutation Origin.
- `GET /api/certificates/verify/:token` — public, strict empty query and 64-character lowercase hex token.

Collections: `clubShowcase`, `certificates`, `certificateVerification`; private `certificateTick` counters on event/registration documents. No real records/indexes/migrations are written during implementation. Existing `_id` indexes provide natural registration and token uniqueness. Suggested reporting indexes (not applied) are certificate user/issuedAt, owner/issuedAt and showcase published/kind/occurredOn. Validity reads are bounded to a 12-certificate page with primary `_id` lookups for each source; future aggregate optimization can replace these without changing privacy rules.

Files: server showcase schema/repository/routes, separate certificate repository, app registration; client API, showcase/editor, issuance/history/print/verification components, seven route pages, navigation/dashboard links, scoped print CSS, dictionary additions and backend/browser tests.

Validation commands: both apps typecheck/lint/build; server `npm.cmd run test:showcase`; client `$env:PLAYWRIGHT_CHANNEL='msedge'; npm.cmd run test:showcase`; `npm.cmd run check:i18n`. Memory transaction fixtures test duplicate issuance, rollback, roles, ownership, attendance corrections, revocation and public projections. Browser tests cover public pages, staff editing/archival, private preview, actual headless PDF generation, issuance/revocation and permission denial. No real certificate is issued or revoked by tests. Real MongoDB transaction and GridFS smoke tests remain an approved staging activity, not part of isolated validation.

Manual path: publish fictional achievement/gallery content; mark a fictional participant present at a started event, issue once and again (same ID), view/print as its recipient, verify publicly (initials only), correct attendance to absent or revoke and refresh verification. A different student must not list the certificate; a non-owner teacher must not issue/revoke it. Never issue/revoke real certificates solely for testing.

Targeted verification complete: 5 certificate/showcase backend tests and 10 desktop/mobile browser tests pass, including malformed URL rejection and actual PDF generation. Both apps pass typecheck/lint/build. Four older authentication integration tests fail in the broader run; see development-roadmap.md. The requested scope ends at 13. Existing event achievements remain on /events; no automatic migration or copying was performed.
