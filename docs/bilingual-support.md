# Milestone 11 — Bangla and English

The shared language preference defaults to Bangla (`bn`) on the server and during hydration. `useSyncExternalStore` reads the saved `ngc-language` localStorage preference after hydration and synchronizes changes across tabs. Invalid/missing preferences fall back to Bangla; storage-disabled browsers retain the choice for the current tab. The global language selector and the existing homepage controls share the same preference. The document's `lang` follows the selected language. No account, session, route, input value or business enum is changed by switching languages.

`client/src/lib/i18n/bn.tsv` is the editable English-key/Bangla dictionary source. `build-translations.mjs` produces `bn.json`; a small number of repetitive loading/refresh/pagination phrases are generated from an explicit Bangla noun dictionary. English is the original key text. `useT` renders translated UI; `Translated` lets server page shells render localized text via a client boundary. Numbered phrases use positional placeholders so their order can differ in Bangla. Parameters are substituted after translation; user names, quiz content, biographies, announcements and private messages remain original content. Generic server-authored notification messages are translated; notification titles remain original source content.

All current screens are migrated: public pages/navigation, auth forms and field validation, membership applications/reviews/directory/profiles/analytics, event management/registration/attendance, faculty/assignments, feedback, announcements/notifications, quizzes/results/reports/performance. Shared FormMessage localizes validation without modifying Zod's validation or server behavior. The toast adapter localizes app messages. Unknown error messages have a localized generic error fallback in error contexts; arbitrary server details are not translated as domain content. Explicit validation messages have Bangla entries, while default Zod messages receive a bounded generic field instruction. Dates/identifiers use their existing unambiguous Gregorian formats; language does not change server UTC calculations or API parameters. Bengali font fallbacks use Noto Sans Bengali/Nirmala UI/Vrinda and responsive readable line-height without adding a font service or package.

Run `npm.cmd run check:i18n` from client/. It builds the dictionary and audits parsed TSX for untranslated JSX and missing literal/conditional/column-label dictionary keys. Dynamic domain text is deliberately outside the dictionary. New features must use `useT` or `Translated` and add Bangla entries. Do not wrap React elements or render functions in the text translator. Dictionary review by a college Bangla speaker remains advisable before public launch.

Affected files: shared language store/hook/selector/toast adapter, dictionary and checks, layout/styles, all feature UI and page shells, shared form errors, Playwright language configuration and language/English regression tests. Existing legacy tests explicitly select saved English; dedicated language tests start with no saved preference and verify the Bangla default and unchanged user content. No packages, backend business changes, live data writes or deployment changes.

Verified: both apps' typechecks/lints/builds passed; all 6 language tests passed on desktop/mobile. The 208-case English UI regression run passed 200 initially; all 8 corrected cases passed on a focused rerun. The translation check passed with 593 UI keys at the Milestone 11 boundary (later features add keys). The migration's initial dropped-label conversion issue was restored and corrected before verification. Browser tests caught numbered-label spacing; parameterized labels restore accessible names. A stale teacher placeholder test from Milestone 08 was updated to reflect actual assigned-activity navigation. No real data/roles/deployments changed.
