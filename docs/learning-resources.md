# Milestone 12 — Science learning resources

Authenticated approved students can browse/search/filter published resources at `/dashboard/student/resources`. Teacher/admin accounts may also browse published resources. `/dashboard/teacher/resources` manages teacher-owned drafts; admins manage all. Categories are Zoology, Botany, Physics, Chemistry, Mathematics and ICT. Titles/descriptions are original content; UI/category labels are bilingual. Search is a bounded literal case-insensitive title search, not a client-supplied regex.

Resources are PDF, note (UTF-8 TXT or PDF), presentation (non-macro PPTX or PDF), or external HTTPS link. Staff create a draft, upload its file if needed, then publish. Published resources must be unpublished before content edits or file replacement. File format cannot change after a file is attached; create a new resource for a different format. Version checks prevent stale edits, publishing and uploads. Archive hides a resource and blocks future downloads; files are retained privately for a future approved retention policy.

Files have a strict 5 MiB request and actual byte limit. The server checks extension/content agreement, PDF header and EOF marker, UTF-8 validity/no NUL for notes, and a bounded PPTX ZIP central directory with required package entries, no encryption, path traversal, duplicate names, macro/binary attachments, ZIP64 or over-50-MiB declared expanded size. It never extracts or executes document content. These are structural/type checks, not a full document parser or malware scanner. Production upload review/malware scanning remains a deployment security consideration.

The existing MongoDB Node.js driver stores files in a private `resourceFiles` GridFS bucket; no external storage account, new dependency or public upload directory. See [official GridFS documentation](https://www.mongodb.com/docs/drivers/node/current/crud/gridfs/). Runtime GridFS may create its standard bucket indexes on the first authorized upload. No live upload/index write is performed during development verification. A temporary upload is linked to a draft using compare-and-set on owner/version; failed conflicts remove the unlinked file, and replacements remove the old file after the metadata commit. Cleanup failures log a generic message and need later orphan reconciliation; no real cleanup script is run.

Downloads resolve a file through its resource's current visibility and fresh membership/owner checks. Arbitrary GridFS IDs are never accepted or exposed in responses. Files stream as attachments with a validated filename, explicit content type, content length, existing nosniff headers and no-store policy. Browser downloads use credentials; no preview executes document content. External links require HTTPS without credentials and open with noopener/noreferrer.

Data: `learningResources` stores content/category/format, server-owned creator/timestamps, published/version/archive fields and private GridFS ID plus name/type/size/SHA-256 metadata. Public-to-approved-member projections omit owner, file IDs/checksums and internal versions. No migration or real data mutation is run. Future indexes: published/category/updatedAt and creator/updatedAt, after approved query-plan review.

API: authenticated `GET /api/resources` and `GET /api/resources/:id/download`; scoped staff `GET/POST /api/manage/resources`, `PUT/DELETE /:id`, `PATCH /:id/status`, `POST /:id/file`, and `GET /:id/download`. Upload uses application/octet-stream and X-File-Name (URI-encoded) / X-Resource-Version. Mutations require trusted Origin; all inputs use allowlists. Collection and file storage dependencies are injectable for tests.

Files: server resources schema/files/repository/routes and app registration; client resource API, bilingual library/form, guarded pages/dashboard links; memory storage/backend tests and intercepted browser tests.

Verification: both apps typecheck/lint/build; server `npm.cmd run test:resources`; client `npm.cmd run test:resources` with Edge and `npm.cmd run check:i18n`. Tests write fictional memory buffers only, never Atlas/GridFS. Manual path: create a fictional resource draft, upload a small permitted document, publish, filter and download as an approved fictional student, then unpublish/edit/archive. Verify a pending member is denied, another teacher cannot replace the file, and a renamed executable or oversized file is rejected.

Verified: both apps passed typecheck/lint/build; 5 resource backend fixture tests and 6 desktop/mobile browser tests passed. The server lint issues for a control-character regex and Buffer globals were fixed. Uploads/downloads use fictional memory storage in tests, not live GridFS. The directory validator has positive PPTX and unsafe entry fixtures. Proceeding to Milestone 13.
